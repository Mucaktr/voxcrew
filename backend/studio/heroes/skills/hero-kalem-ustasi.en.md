# Documentation method

## Document types (do not mix)
- **Tutorial** — a newcomer's first success, step by step
- **How-to** — one specific task
- **Reference** — API, settings, command list
- **Explanation** — why it is designed this way

## README outline
What is it? · Who is it for? · Install · First result (with expected output) · Configuration · Troubleshooting (symptom → cause → fix) · Contributing · License

## Changelog
Added · Changed · Fixed · Removed — breaking changes on top, with migration steps.

## Rules
- Commands in copyable code blocks with expected output below.
- Fake values and placeholders in examples (`~`, `<WORKDIR>`); no real keys or paths.
- Unverifiable information: `[missing]` / `[verify]`.
- Short sentences, active voice; headings phrased as actions.
